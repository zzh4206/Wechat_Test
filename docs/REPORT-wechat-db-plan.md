## 0. 阶段目标与最高原则（产品负责人 2026-10-11 指示）

**第一阶段唯一目标：在严格监管下"读到"群聊消息。** "读到什么有用的东西"（哪些人、哪些方面）是第二阶段的事。

由此确立**管控三原则**（优先级高于一切工程便利）：

1. **默认全拒**：任何群，未出现在用户维护的白名单配置里，读取层一个字节都不碰。白名单是读取层的第一道闸（在适配器最前端），不是下游缓冲层的过滤器；
2. **白名单 = 用户手工维护的显式清单**（chatId 逐条列出），不做"发现新群自动加入"类便利功能；
3. **读取行为可审计**：读哪些群、每次读了多少条、何时读的，留本地审计日志（只记元数据，不记内容）。

红线沿用路线报告 §3：只读本机本人库（被动只读）；禁协议逆向；UI 自动化发送二期再议。

## 2. 任务拆解（按依赖序，可直接分派编码 agent）

### W1 · 生死步：本机微信库可读性 spike（~0.5 天）⚡ 先行
- **目标**：回答"这条路通不通"。
- **产出**：`docs/REPORT-db-access.md` + `spikes/db-probe.mjs`（只读脚本）
  1. 定位本机微信（4.x）聊天库：`~/Library/Containers/com.tencent.xinWeChat/...` 下的 msg db 文件清单与大小；
  2. 判断加密形态：能否直接 SQLite 打开？SQLCipher？（key 线索：登录态/keychain/配置文件，参考社区工具 wechat-dump-rs 等的 macOS 实现，**只读参考其思路**）；
  3. 若可打开：列出表结构，找到 `@chatroom` 会话消息表、确认含群消息的字段（发送者、时间戳、内容、IsSender）；
  4. 记录所需 macOS 权限（完全磁盘访问/钥匙串）；
  5. 风险注记：微信版本号、库 SHA、发现过程可复现。
- **验收**：三选一明确结论（明文可读 / 需 key 且 key 可得 / 不可行）；不可行则项目 D1 终止，报告说明死因。
- **红线**：只读；导出的任何样例数据脱敏且不入仓库；禁止写微信目录。
- **commit**: `docs(spike): W1 微信本地库可读性验证`

### W2 · 读取适配器 + 白名单硬闸门（1 天，依赖 W1 通过）
- **目标**：`src/source/wechat-db.ts`——以 MessageSource 接口产出消息，白名单闸门在适配器第一行。
- **要点**：
  - 配置 `groups` 白名单升级为读取层强制项：适配器初始化时若白名单为空 → 拒绝启动（fail-closed，对应"严格管控"）；
  - 白名单值用群 chatId（`xxx@chatroom`）；W3 提供群名→chatId 的查询辅助，但配置本身只认 chatId；
  - 审计日志：`<stateDir>/audit.log` 只记 `{ts, chatId, count}`，不记内容；
  - 轮询间隔可配置（默认 10s）；单实例 flock；不碰微信进程/窗口。
- **验收**：白名单外的群在适配器层零读取（测试断言）；白名单为空时启动即失败；audit.log 无消息内容。
- **commit**: `feat(source): 微信本地库读取适配器 + 白名单硬闸门 + 审计`

### W3 · 消息规范化（1 天，依赖 W2）
- **目标**：把库里的原始行变成管线认得的 `{chatId, sender, senderName, text, messageId, ts}`。
- **要点**：发送者剥离（`wxid:\n正文` 形态，参考移植报告 §3.1）、系统消息过滤（拍一拍/撤回/入群退群）、wxid→昵称映射（联系人库，映射表缓存于 stateDir）、超长与媒体消息降级为占位符 `[图片]` 等（MVP 只处理文本）。
- **验收**：规范化快照测试用例（构造假 db 行）；昵称映射缓存生效。
- **commit**: `feat(source): 群消息规范化——发送者剥离/系统消息过滤/昵称映射`

### W4 · 增量游标与历史回灌（0.5 天，依赖 W3）
- **要点**：每群记录已读位点（stateDir 持久化）；启动默认只读增量；`backfillOnStart: N` 可配置回灌最近 N 条（默认 0，受监管原则：不悄悄扩大读取面）。
- **验收**：重启不重复不漏；backfill=0 时零历史读取。
- **commit**: `feat(source): 增量游标与可选历史回灌`

### W5 · 管线合流与 D1 验收（0.5 天，依赖 W4）
- **要点**：bus.ts 切换到新消息源（保留旧 im-connect 事件代码路径为死代码或删除，说明取舍）；端到端模拟：假库 → 适配器 → buffer → distiller(mock llm) → journal 全链测试；RUNBOOK（安装/授权/白名单配置/审计查看/卸载）。
- **验收**：全测试绿；白名单外群全程零触及；dispose 干净。
- **commit**: `release: D1 受监管读取端到端联调`

**依赖图**：W1 → W2 → W3 → W4 → W5（串行为主；W3 与 W4 可在 W2 接口定稿后并行）。
