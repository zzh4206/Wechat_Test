## 0. 总体方案（一段话）

KeyboardSender 的键序从"依赖当前会话"升级为"AX 侧栏自定位"：

```
激活微信（1.5s 空间动画稳定等待）
  → AX 遍历侧栏：定位 session_item_文件传输助手 行（精确名匹配，缺失/重名即 defer）
  → 合成鼠标点击该行中心 → 轮询确认 chat_message_list 出现（会话已打开，合规闸天然成立）
  → 剪贴板设为消息 → Cmd+V → Return（发送）
  → 2s 后 DB 回读验证 #l<id>（P0 兜底闸，保留不变）
```

**权限面**：仅需「辅助功能」（已授权）——不需要屏幕录制（验证走 DB 回读而非截图）。
**实现载体**（WP-AX2 内决策）：Swift 编译小工具（wechat-ui 先例）或 python pyobjc 脚本（wechat_db.py spawn 先例）——以 AX 原生 API 直连为硬要求（System Events 桥已实证不可靠）。

## 工作包 1：AX 能力实证（0.5 天 · 闸门 G1）

**工作内容**：
1. 最小 AX 探针：原生 AX API（Swift 或 pyobjc）对准本机微信 4.1.13，遍历侧栏 `session_item_*` 行，dump 全部会话名；
2. 实证三项：① 文件传输助手行存在且标识符可精确匹配；② 点击行中心 → `chat_message_list` 出现（会话打开确认判据）；③ 行回收/滚动行为与本机窗口布局的适配；
3. 顺带实测：AX 树懒物化时序（何时需要唤醒/重试）、深度与节点规模（定遍历上限）。

**交付**：`docs/REPORT-ax-probe.md`（真实 AX 树 dump + 三项实证结论）。

**闸门 G1**：三项全过 → 进入工作包 2；任一不过 → 本计划暂停，回到调查报告补充方案（不硬上）。

## 工作包 2：AX 定位模块（1 天 · 依赖 G1 通过）

**工作内容**：
1. 载体决策（二选一，说明理由）：Swift 编译小工具进 macos-wechat-export（wechat-ui 先例，零 python 依赖）/ pyobjc 脚本（复用现有 python spawn 通道，需装 pyobjc）；
2. 实现 `locate-and-open` 原语：
   - 遍历侧栏 `session_item_*` 行（深度 ≤40、批量属性读、(name, y) 键控——wechat-mcp 对策照单）；
   - 精确名匹配"文件传输助手"行（重名：取第一并审计 duplicate_name；缺失：defer，绝不模糊匹配）；
   - 合成鼠标点击行中心 → 轮询 `chat_message_list` 出现（超时 5s → defer）；
   - 剪贴板保存/恢复语义保留；
3. 交互闸与频控语义不变（用户空闲 <10s 或当日超限 → defer，不抢前台不点击）。

**交付**：定位原语 + 单测（mock AX 树：命中/缺失/重名/树未物化四场景）。

## 工作包 3：sender 集成（0.5 天 · 依赖工作包 2）

**工作内容**：
1. KeyboardSender 键序重构为两段：**定位段**（locate-and-open 原语）+ **发送段**（现状的粘贴+回车不变）；
2. 段间状态语义：定位失败 → defer（attempts 不增，等用户/环境恢复）或按原因计 attempts（发送前失败类）；定位成功 → 发送段执行 → `sent_pending_verify` → 回读验证（状态机全部保留）；
3. Config：`sendTarget`（默认 'filehelper'，**常量语义**——禁止配置成其他会话/群聊，代码级只认 filehelper）；
4. `dailyReportTime` 恢复 20:30；sendTestSample 适配新键序。

**交付**：集成后的完整发送链路 + 状态机测试更新（离线 mock AX 树：命中/缺失/重名/树未物化四场景）。
