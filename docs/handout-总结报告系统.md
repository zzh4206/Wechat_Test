# Handout：微信群聊总结报告系统

> 一页看懂报告怎么生成、长什么样、为什么这样设计。
> 完整规范见：[功能文档 §5](功能文档-微信群聊分析与提醒助手.md) · [报告模板](报告模板.md)

---

## 1. 一句话定位

**把「刷群」变成「看摘要 + 收提醒」**：每天/每周/每月自动从群聊原始消息中生成结构化报告——结论先行、变化优先、条条可溯源；推送纯文本到微信（手机看），同步落盘 Markdown（电脑查）。

## 2. 设计依据：三套成熟范式

| 范式 | 来源 | 我们取什么 |
|---|---|---|
| 金字塔原理 | McKinsey / Barbara Minto | 结论先行：研究自下而上归纳，呈现自上而下展开 |
| BLUF / Key Judgments | 情报简报规范 | 报告第一页放 3–5 条可独立成立的「关键判断」，只读第一页不漏事 |
| 结构化摘要 | IMRAD 固定槽位 | 固定槽位标签，读者扫标签而非通读文字 |

## 3. 三条硬性写作原则

1. **结论先行**——每个板块第一句是判断句（✅「报销标准定了：上限 500/天，下周一生效」；❌「今天群里讨论了报销」）；
2. **变化优先**——只详述与上期相比的变化，无变化话题折叠成一行；
3. **条条可溯源**——每条判断挂证据指针（群·时间·发送者），正文可短，证据永远在。

## 4. 三层结构（按阅读时间递进）

```
┌ L1 一分钟层（必有）────────────┐
│ 标题导语（谁/什么事/什么变化）      │
│ 关键判断 3–5 条（编号陈述句）       │
│ 今日行动（我的任务 + 他人承诺到期）  │
├ L2 五分钟层（必有）────────────┤
│ 按话题组织（非按群流水），每话题：    │
│ 【变化】→【现状】→【相关人】→【待观察】│
│ 重点人板块（可选）· 双向任务看板      │
├ L3 溯源层（按需展开）───────────┤
│ 原文引用 · 文件增量 · 条目变更记录   │
└──────────────────────────┘
```

- **报告种类**：单群日报（20:30）→ 跨群总览（同日合并）→ 周报（周日）→ 月报（1 日）；支持手动补生成任意区间，不影响后续正常节奏。
- **双向任务看板**：「我欠人的」（F4 任务）与「人欠我的」（F8 他人承诺）并列，周报看四态（新增/临近截止/逾期/完结），月报看出兑现率。

## 5. 双格式输出：一份内容，两种皮肤

| | 微信文本版 | Markdown 存档版 |
|---|---|---|
| 场景 | 手机竖屏、地铁上扫一眼 | 电脑检索、回溯引用 |
| 形态 | 纯文本 + Unicode 符号排版 | 完整 md（表格/引用块/跳转路径） |
| 范围 | L1+L2 全量，L3 超长转「附录」按需取用 | 全量 |

**微信版符号系统**：`▍`层 · `▸`话题 · `★`判断句 · `☐/◑`待办 · `⚠️`逾期 · `【】`固定槽位
**硬约束**：每行 ≤30 中文字符主动折行；表格一律竖排；文件路径不进微信版；消息头固定 `报告类型｜范围｜日期`。

## 6. 成品长什么样（微信版日报节选）

```
日报｜项目群｜10月13日

▍L1 一分钟

★报销标准定了：上限500/天，
下周一(10.20)生效
（项目群·10:32·王磊）

1. 服务端联调推迟到周四，
   原因：测试环境没就绪

今日行动
· ☐ 把接口文档发李强（18:00前）
· ◑ 等张三的数据表（明早到期）

▍L2 五分钟

▸ 话题：报销标准
【变化】★上限从300提到500
【相关人】王磊主张提高；
财务刘敏同意但要求发票合规

▸ 双向看板
· 我欠人：接口文档→李强 ☐今18:00
· 人欠我：张三-数据表 ☐明早
```

## 7. 质量护栏

- **长度红线**：L1 ≤200 字；日报 L2 ≤800 字、周报 ≤2000、月报 ≤3000；
- **置信度降级**：L1 关键判断逐条打置信度，低置信自动降到 L2；
- **空槽省略**：无内容的槽整槽消失，唯「今日行动」空时显式写「今日无待办」；
- **反失真**：任何概括必须有原文指针兜底，杜绝无出处的引用；
- **红线不变**：报告只推给自己（文件传输助手/通知中心），绝不进任何群聊。
