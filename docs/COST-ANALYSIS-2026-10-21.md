## 3. 根因链（三个缺陷叠加，全部可修复）

### 3.1 失败后触发条件不收敛 → 重试风暴（元凶，占浪费 ≥80%）
`src/distiller.ts`：
- `tryDistill` 失败路径**不更新 `lastDistill`、不清零 `counters`**；
- `onNewMessage` 判据 `n >= distillEveryMessages` 中 n 只增不减 → **失败后每条新消息都触发一轮全量重提炼**；
- `tick()` 每 30s 对 counters 中所有群判 `now - lastDistill >= 15min`，从未成功过的群 `lastDistill=0` → **每 30s 必触发**。
两路叠加：活跃群每来一条消息跑一轮（每轮 2 批 × 重试 = 最多 4 次调用）。10-20 的 1948 次即由此而来。

### 3.2 每次提炼喂整个 buffer → 重复提炼（正常态浪费，占 ≥50% 输入）
`buffer.snapshot(chatId)` 返回最近 `bufferSize=60` 条。每 25 条触发一次 → 每次调用中 **~60-70% 消息是上次已提炼过的重复内容**。即使零失败，这也是纯浪费。

### 3.3 观测缺口导致 5 天后才发现
`llm-calls.jsonl` 只记 `errKind(timeout|other)`，不记错误摘要 → "other" 的真身（限流？5xx？鉴权？）至今不可见；无错误率指标、无成本熔断，直到费用曲线爆掉才暴露。

## 4. 优化方案（分级，均不换模型、不降报告质量）

### C1（P0，止血）：失败熔断 + 指数退避 + 错误可见
- 失败后退避：该群下次允许提炼时间 = now + min(30min, 1min × 2^k)，k= 连续失败次数；**成功清零**；
- 熔断：连续 ≥5 次失败 → 该群 distiller 暂停 1 小时 + notify 告警一次（dry_run 语义）；
- 失败不再让 counters 无限触发（失败只消耗一次尝试机会，不看消息条数）；
- errKind 细分：`rate_limit(429) / auth(401/403) / server(5xx) / bad_request(400) / timeout / other`，JSONL 增 `errMsg`（redact 后 ≤160 字符）——**先让错误可见，再谈优化**；
- 预期：失败风暴归零。此项单独就将 10-20 的 ¥34.87 降到 ≤¥1。

### C2（P0，去重复）：distiller 增量水位
- 记录每群 `lastDistilledMsgId/ts`（持久化，与 insights 同目录），snapshot 后**只喂水位之后的新消息**；水位在成功提炼后推进；
- 首个无水位的历史群按 `distillEveryMessages` 条滚动初始化（不回灌历史）；
- 预期：每次调用输入降 50-70%，distill 成本再降一半以上。

### C3（P1，输入瘦身）：消息 JSON 精简
- 现状每条消息序列化全部字段（`msgId/quoteOfMsgId/fileId/rawClass/...`），且 `text` 二次 JSON 字符串化（引号全转义）；
- 改为紧凑行格式：`{n,name,ts,text}`，长文本截断 300 字（保留序号溯源），非文本消息（表情/图片占位）剔除或折叠为 `[图片]`；
- 预期：输入 tokens 再降 20-35%，对归纳质量无实质影响（信息密度提升）。

### C4（P1，缓存）：固定前缀命中 GLM 上下文缓存
- 指令区（人格+schema+约束，约 600-900 tokens）逐字节稳定、置于最前 → 命中智谱上下文缓存，输入价 8→2 元/百万（省 75%）；
- `llmPricing` 增加 `cacheInput` 价并统计口径区分；报告尾注明缓存命中估算；
- 预期：指令区部分的输入费用降 75%。

### C5（P2，选项，未采用）：换小模型/批处理 API
- GLM-5.3-Flash（0.8/2.8）跑 distiller 可再降 90%，但违背"同模型"约束，且洞察质量需评测——留作选项；
- 智谱 Batch API 5 折，适合日报（非实时），但宿主 llm 服务暂无批处理通道——留作后续。

### 效果预估（同模型、同 prompt 质量）

| 阶段 | 群A 日成本 | 30 群年化 | 相对现状 |
|---|---|---|---|
| 现状（10-20，群A） | ¥34.87 | ≈¥12,700 | — |
| +C1 止血 | ≈¥1.2 | ≈¥440 | -93% |
| +C2 增量水位 | ≈¥0.55 | ≈¥200 | -97% |
| +C3 瘦身 +C4 缓存 | ≈¥0.30 | **≈¥110** | **-98%** |

即：修复后 30 群一年的成本 ≈ 现状 585 单群 3 天的开销，回到你估算的 ¥1,000 量级以下。且报告质量不降——C1/C2 减少的是重复与失败调用，C3 提升信息密度，C4 只影响计费。
