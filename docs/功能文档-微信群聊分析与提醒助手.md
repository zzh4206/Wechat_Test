# 功能文档：微信群聊分析与提醒助手

> 版本：v0.3（讨论稿）
> 日期：2026.10.13
> 定位：**纯分析系统，不发言**。只读取本账号已加入群聊的本地消息数据，做总结、统计、事件与任务记录，以及主动提醒（提醒仅发给自己，不进入任何群聊）。
> 前置依赖：读取层技术路线见 [技术报告-mac端微信群聊读取与应答.md](技术报告-mac端微信群聊读取与应答.md)。本文档只描述功能，不涉及实现。

---

## 1. 产品目标

在不动微信、不在群里发任何消息的前提下，把「刷群」变成「看摘要 + 收提醒」：

1. 我关心的人说了什么，随时可查、按期总结；
2. 每个群有独立、持续累积的数据资产；
3. 每天/每周/每月自动收到结构化报告；
4. 群里有人给我发消息/回应我，自动识别、记录、按时提醒；
5. 群里的关键事情（重要事情、@所有人通知、deadline）不遗漏。
6. 群里有文件下载给出索引，给出类型、摘要等。

**明确的非目标**：
- 不自动回复、不在群里发任何消息；
- 不做自动入群；
- 不上传原始聊天记录到外部服务（LLM 调用仅传必要的脱敏摘要上下文，见 §7 隐私）。

## 3. F1 指定人物发言追踪

### 3.1 关注名单（Watch List）

- 用户维护一张**全局关注名单**（跨群生效），并可按群设置**群内关注子集**。例：全局关注张三；在「项目群」里额外关注李四。
- 名单条目：人物（wxid + 显示名，含群昵称别名）、备注（此人是谁、我为什么关注他）、生效群范围。
- 人物识别必须能穿透群昵称：同一个人在不同群里昵称不同，需按 wxid 归一。

### 3.2 发言提取与总结

- **按需查询**：选中某人 + 某群 + 时间段，输出：发言时间线（原文）、按话题聚类的内容摘要。
  - 注：**纯发言量统计默认不做为独立产出**（「谁话多」对决策帮助有限）。发言量只作为内部信号用于两处：报告中的环比趋势（判断某人活跃度是否突变，突变才值得一提）、以及总结时对话题簇的排序权重。
- **跨群视图**：某人在所有群（或所有被追踪群）的合并发言流，按时间排列。
- **增量摘要**：对关注人物的发言按天滚动生成增量摘要，长对话可折叠为「他最近在忙什么」级别的一页速览。
- **引用回复链（Quote-Reply Chain）**：微信消息支持「引用回复」，且实践中大量回答以引用他人消息的方式出现。要求：
  1. 识别引用关系，把「被引用的原文 + 引用者的回答」作为**一条完整对话单元**保存和总结，而不是把两者拆开各算各的；
  2. 总结某人发言时，其引用的他人原文**计入他的语境**（他引用来支持/反驳什么），被引用者的话作为归属清晰的上下文，不与发言者本人的观点混淆；
  3. 无引用标记的纯文字回复（直接接话、@回复）尽力通过时序 + 语义相近性做**软关联**，关联置信度低时只展示不强行合并；
  4. 引用链支持多级追溯（A 引用 B，B 曾引用 C），可展开完整脉络查看。
- **上下文保留**：总结时应保留发言前后的少量他人消息作为兜底上下文，避免把「回复别人的一半对话」总结错；与引用链互补——先走精确的引用关系，缺失处再用邻接消息补足。

### 3.3 交互要求

- 支持按人检索：关键词 + 人名 → 该人所有含此关键词的发言及出处（群、时间）。
- 支持把某人某段发言「一键收藏」到关键事件库（与 F5 打通）。

## 4. F2 群聊独立数据空间

### 4.1 设计原则

每个群是一个**独立的数据桶**，互不污染：

- 独立的消息库（消息、发送者、时间、已处理状态）；
- 独立的统计口径（消息量、活跃度、成员分布）；
- 独立的报告（每个被追踪群可单独出日报）；
- 独立的事件库与任务库（A 群的任务不会串到 B 群）。

### 4.2 群级配置

每个群可单独配置：

| 配置项 | 说明 | 默认 |
|---|---|---|
| 是否追踪 | 不追踪的群只落库不分析 | 追踪 |
| 群内关注人物 | 本群的 F1 详解对象 | 继承全局名单 |
| 报告开关与节奏 | 是否出报、日报/周报/月报各自开关 | 日报开 |
| 报告送达位置 | 通知中心 / 文件传输助手 / 仅存档 | 文件传输助手 |
| 关键词白名单 | 命中即标记为疑似关键事件的词 | 空 |
| 免打扰 | 静默，但仍可事后查询 | 关 |

## 5. F3 定期报告

### 5.1 报告节奏

| 报告 | 生成时间 | 内容颗粒度 |
|---|---|---|
| 日报 | 每日固定时间（默认 20:30），汇总当天 | 当日话题、待办、关键事件 |
| 周报 | 每周日 20:40 | 一周主线 + 与上周对比、关联 |
| 月报 | 每月 1 日早晨 | 月度沉淀，侧重变化与结论 |

支持手动触发「立即生成截止到当天的（日、周、月）报告」，且之后按照默认情况生成的日、周、月报告内容不受这个影响。

### 5.2 报告结构（v2：三层金字塔）

> 设计依据（调研结论）：让读者「快速掌握」的关键不是按信息来源组织报告，而是**按读者的注意力梯度组织**。借鉴三套成熟范式：
> 1. **金字塔原理**（McKinsey, Barbara Minto）：结论先行、自上而下——核心判断 → 支撑主题 → 底层证据，每层回答「所以呢？」，下层只为上层服务；
> 2. **情报简报 BLUF / Key Judgments**（情报界写作规范、[UNODC SOCTA 手册](https://www.unodc.org/documents/organized-crime/SOCTA_Handbook.pdf)）：报告开头放「关键判断」编号清单，每条是可独立成立的完整陈述句，读者只读第一页也能带走全部结论；
> 3. **结构化摘要**（IMRAD 式固定槽位）：各节用**固定标签**，读者扫标签而非通读文字。另外「研究是自下而上的，呈现必须自上而下」——生成过程从消息逐级归纳，报告呈现则从结论向下展开（[CX Pyramid 应用示例](https://adoreboard.com/cx-pyramid-principle/)）。

#### 5.2.1 三条硬性写作原则

1. **结论先行，全文无一例外**：每个板块第一句是加粗的**判断句**（「XX 的事定了：用方案 B」），不是过程描述（「今天群里讨论了 XX」）。判断句必须完整，脱离上下文也能懂；
2. **变化优先于存量**：优先报告「与上期相比变了什么」（新决定、新承诺、新矛盾），无变化的话题折叠为一行「无变化」清单置底；
3. **条条可溯源**：每条判断挂证据指针（群名+时间+发送者），点击展开原文。**正文长度与证据深度解耦**——正文可以很短，证据永远在。

#### 5.2.2 报告分层（按阅读时间递进）

**L1 一分钟层（必有）——只看这一层也不漏事**

- **标题导语**：一句话概括本期最重要的事（新闻导语式：谁 / 什么事 / 什么变化）；
- **关键判断**：3–5 条编号的完整陈述句，按重要性排序（Key Judgments 式），覆盖：新决定、新任务/新承诺、deadline、与我直接相关的事；
- **今日行动**：从 F4/F8 提取「今天要我做的」与「今天应到期的他人承诺」，无则省略此槽。

**L2 五分钟层（必有）——按话题组织，不按群流水**

- 每个话题簇一节，固定槽位标签：**【变化】**（本期进展/转折）→ **【现状】**（一句话背景）→ **【相关人】**（谁主张、谁反对、谁承诺了什么）→ **【待观察】**（悬而未决的点）；
- 话题排序：「与我的相关度 > 新鲜度」；
- **重点人板块**（F1 定期化，作为 L2 可选槽位保留接口）：每个关注人物一小节——本期立场 / 承诺 / 与我相关发言，同样「一句判断 + 证据指针」；
- 双向任务看板（我欠人的 / 人欠我的，引自 F4/F8）在此层末尾；群概览统计压缩为一行数据摘要。

**L3 溯源层（按需展开）——证据与原文**

- 值得回看的原文引用（3–10 条）：群名 + 时间 + 发送者 + 原文全文；
- 本期文件索引增量（引自 F7）；
- 事件/任务/承诺的完整条目变更记录（引自 F4/F5/F8）。

> 说明：跨群汇总报告同样走三层——L1 合并所有群的关键判断，L2 每群一节，L3 统一放证据。
> 原「全群概览 + 重点人详解」的悬置问题在 v2 中的处理：概览降级为 L2 末尾的一行数据摘要，重点人降级为 L2 可选槽位——两者都不再占据报告开头的黄金位置。

### 5.3 报告聚合策略

- 多群并存时：每群一份独立日报（因 F2 数据独立）+ 一份**跨群汇总**（把所有群的 TL;DR 和任务合并成一封「今日总览」，避免逐群翻看）。
- 周报/月报默认只出跨群汇总 + 每群一节。

## 6. F4 任务识别与提醒

### 6.1 识别范围

只识别**与我有关的任务指派**，不识别群里泛泛的工作安排（避免噪音）：

- 明确指派：消息中出现 @我 / 我的昵称 / 称呼 + 动作要求（「帮我查」「把xx发我」「记得」）；
- 我承诺的任务：我回复「好的」「收到」「我来」等确认语义的消息，自动关联为已接受任务；
- 时间线索：相对时间（「今天内」「下班前」「周五之前」）与绝对时间（「下周一」），无法解析时限的任务标记为「无明确 deadline」，并在当天晚上生成日报的时候提请审批具体时间，并按默认时限（3 天）软提醒。

### 6.2 任务记录

每条任务包含：来源群、派发人、原文引用、任务描述（LLM 提炼）、截止时间（解析值 + 置信度）、状态（待确认 / 进行中 / 已完成 / 已取消）、提醒计划。

- 生命周期：识别 → **待确认**（推送通知让我确认是不是真任务）→ 确认后进入正式清单 → 完成/取消需手动勾选；
- 误报处理：识别结果先经「待确认」（在日报提出）环节，避免把闲聊当任务；确认过一次的「派发人 + 句式」模式会被记住，同类消息下次可直接入清单。

### 6.3 提醒策略（双通道）

| 时点 | 系统通知 | 微信自发消息 |
|---|---|---|
| 任务识别时 | ✅（待确认卡片） | ✅（任务摘要 + 原文引用） |
| 截止前 1 天 | ✅ | ✅ |
| 截止前 1 小时 | ✅ | 可配置，默认关 |
| 逾期未完成 | ✅（升级样式） | ✅（附逾期标记） |

- 微信自发消息通道：仅向**文件传输助手或我给自己的消息**发送，绝不发到任何群（与 §1 非目标一致）；
- 每日 7:50 自动发送「今日待办速览」，合并当日到期任务一次性推送。

## 7. F5 关键事件记录

### 7.1 入库方式

1. **自动识别**（推荐模式）：LLM 在增量分析中识别以下类别并入库，标注置信度——
   - 决定/结论（「定下来了：用方案B」）；
   - 约定/承诺（时间、地点、谁做什么）；
   - deadline 与日程（会议、交付、报名截止）；
   - 重要变更（价格、规则、人事、计划变动）；
   - 与我直接相关的一切（@我、提到我的名字/项目）。
2. **手动标记**：任何消息可一键标记入库；用户可用自然语言补记（「记住：周四要交材料」），系统归一到事件库并打来源标签「手动」。

### 7.2 事件条目与使用

条目：类别、一句话描述、原文引用、来源群、涉及人物、时间/截止、置信度、来源（自动/手动）、状态（有效/已被后续消息推翻/过期）。

- **冲突处理**：后续消息推翻既有事件（「改到周五」）时，自动关联为新版本，旧条目标记「已更新」而非删除，保留演变链；
- 检索：按群、人、时间、类别、关键词组合查询；
- 报告联动：F3 报告的第 4 节直接引用事件库的增量。

## 8. F6 提醒推送通道

| 通道 | 用途 | 限制 |
|---|---|---|
| macOS 通知中心 | 即时提醒（任务、识别确认、报告完成） | 简短，点击进详情 |
| 微信自发消息（文件传输助手） | 可回看的推送：报告全文、任务摘要、每日速览 | 仅发给自己，发送前走 dry_run 校验 |
| 本地报告存档 | 所有报告与事件的落盘归档，支持导出 | 永久留存，受保留策略约束 |

通道可按事件类型独立开关（如「逾期提醒走双通道，报告仅走微信」）。

## 9. F7 文件整理

对群聊中出现的**文件类消息**（文档、表格、压缩包、图片/视频按需纳入）单独建索引，解决「群里发过的文件找不到」的问题。

### 9.1 文件索引

- 每个群独立一份文件索引（沿用 F2 数据桶原则），条目包含：文件名、类型/扩展名、大小、发送者、发送时间、所在群、微信内存储路径；
- 类型自动归类：文档（pdf/docx/pptx）、表格（xlsx/csv）、压缩包、代码/文本、图片、视频、其他；
- 重复检测：同名/同哈希文件合并为一条索引，保留多次转发的出现记录，避免同一个人连发三遍占三页。

### 9.2 摘要与整理

- **文件定位**：索引记录微信缓存中的文件实际路径，用户可直接打开；文件本体支持从微信内下载落盘，系统只负责定位路径，**不复制、不归档文件本体**，磁盘占用可忽略；
- **自动摘要**：对文档类文件生成一句话内容摘要 + 关键词，让索引「看名字和摘要就知道是什么」；
- **上下文标注**：提取文件发送前后的相关讨论（结合 F1 的引用回复链），标注「这个文件是干什么用的、谁要的」——很多文件价值不在文件本身而在那条「这是最终版，用这个」的消息；
- **版本链**：同一事务的迭代文件（「初版 → 修改稿 → 最终版」）按命名相似性 + 时间邻近 + 上下文关联成版本链，旧版本折叠，突出最新版，并保留完整演变记录。

### 9.3 检索与联动

- 检索：按群、发送者、类型、时间、文件名/摘要关键词组合查询；
- 报告联动：日报/周报中新增「本期文件」小节，列出新文件及其摘要，重要文件（被多人引用、上下文含 deadline 语义）标注星标；
- 事件联动：文件可作为 F5 关键事件的附件引用（如「会议纪要.pdf」挂在对应事件条目下）。

## 10. F8 他人承诺追踪

与 F4 **对等**的另一半：F4 记录「我欠别人的」，F8 记录「别人欠我的」——别人在回复我的消息中承诺了什么时候给我什么东西。

### 10.1 识别范围

只识别**指向我（或我方事务）的他人承诺**，不记录群里泛泛的他人间约定（避免噪音）：

- 直接承诺：他人回复我的消息中包含交付语义（「我晚点发你」「明天给你」「下周一前把报表发群里」且上下文是回我的请求）；
- 承诺触发识别：优先识别**我发起请求后**（「能发我一份吗」「什么时候有结果」）他人的应答；我没有显式请求但对方主动许诺给我的，也纳入；
- 承诺变更：后续消息改变时限或内容（「延期到周五」「改发压缩包」）时，按 F5 的演变链方式更新原承诺而非新建；
- 兑现识别：对方实际发出文件/答复后，自动关联原承诺并标记「已兑现」，生成兑现记录（承诺时间 vs 实际时间）。

### 10.2 承诺记录

每条承诺包含：来源群、承诺人、我的原始请求（如有，含原文引用）、承诺内容（LLM 提炼）、承诺时间/交付物、截止时间（解析值 + 置信度）、状态（待确认 / 等待中 / 已兑现 / 已跳票 / 已取消）、提醒计划。

- 生命周期：识别 → **待确认**（在日报/通知中让我确认是不是真承诺）→ 确认后进入「等待中」→ 兑现/跳票/取消；
- 兑现需自动识别成功 + 允许我手动勾选兜底；
- 「已跳票」不删条目：逾期未兑现自动标记，并在后续日报中持续出现在「人欠我的」清单里，直到我手动关闭。

### 10.3 提醒与催办

| 时点 | 系统通知 | 微信自发消息 |
|---|---|---|
| 承诺识别时 | ✅（待确认卡片） | ✅（承诺摘要 + 原文引用） |
| 承诺截止当天 | ✅ | ✅ |
| 逾期未兑现 | ✅（跳票标记） | ✅ |

- **催办提示（生成内容，不代发）**：逾期时可为我生成一条得体的催办话术草稿，**仅展示在本地/文件传输助手中供我复制**，系统绝不把任何内容发进群聊（与 §1 非目标一致）；
- 报告联动：F3 报告的「任务看板」扩展为**双向看板**——「我欠人的」（F4）与「人欠我的」（F8）并列，一眼看清两边的时间差与压力。

## 11. 隐私与安全要求（沿用技术报告原则）

1. **不侵入**：只读本机微信本地库，不碰微信进程、不伪造协议；
2. **数据不出本机**：原始聊天记录只在本地；送 LLM 的内容最小化（只传完成总结/识别所必需的消息片段），事件库与报告本地落盘；
3. **保留期**：群聊原始消息涉及第三人，本地日志与原文缓存设置保留期（建议默认 90 天，可配置），报告与事件摘要可长期保留；
4. **无群内行为**：系统在任何情况下不向群聊写入内容；自发消息通道仅限文件传输助手，发送层保留 dry_run、前台检测闸门；
5. **单实例与闸门**：沿用 flock 单实例、STOP 开关、presence 闸门等既有设计。

## 12. 边界与风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 读取层失效 | 微信版本升级破坏本地库读取（技术报告 §2.1） | 适配器接口隔离；上线前先验证读取可行性 |
| 任务误识别 | 把玩笑/闲聊当任务，或漏掉隐晦指派 | 「待确认」环节 + 置信度阈值 + 模式学习 |
| 时间解析错误 | 「下周三」「尽快」等模糊时间 | 保留原文引用，提醒中注明解析依据，允许手动修正 |
| 总结失真 | LLM 概括歪曲某人发言 | 报告强制附原文引用（§5.2 第 6 节），可溯源核对 |
| 隐私 | 分析对象是真实第三人的言论 | 本机处理、保留期限制、不对外分享报告含原文的版本 |
| 承诺误识别 | 把普通应答当成交付承诺 | 「待确认」环节 + 置信度阈值（社交圈内表达直接，误报率预期低） |

## 13. 里程碑建议（按风险排序）

1. **M0 读取层验证**：本机当前微信版本能否稳定读取群消息（决定一切的前提）；
2. **M1 群数据空间**：分群落库、发送者剥离与 wxid 归一、群画像统计（F2）；
3. **M2 人物追踪**：关注名单 + 发言提取与总结（F1）；
4. **M3 报告**：日报 → 周报 → 月报，含跨群汇总（F3）；
5. **M4 任务与事件**：任务识别 + 双通道提醒（F4/F6），关键事件库（F5）；
6. **M5 承诺与文件**：他人承诺追踪（F8）、文件索引与摘要（F7）；
7. **M6 打磨**：误报学习、引用回复链优化、冲突演变链、导出与归档。
